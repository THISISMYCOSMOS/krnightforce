# 기준선 실험 실행 절차서 (사용자 PC)

midnight-expert가 필요한 세 가지 실험을 사용자 PC의 Claude Code에서 돌리는 절차입니다. 실험의 목적과 관문은 `docs/plan.md` 8절(기준선 실험)에 있습니다. 집계와 우리 엔진 결과와의 비교는 결과를 받은 쪽이 합니다.

## 0. 준비 (한 번)

1. Claude Code에 midnight-expert를 설치합니다.
   ```
   claude plugin marketplace add midnightntwrk/midnight-expert
   ```
   설치 뒤 `/plugin`으로 compact-core가 켜져 있는지 확인하고, 설치한 midnight-expert 커밋을 적어 둡니다(`git -C <설치 경로> rev-parse HEAD`).
2. Compact 컴파일러 0.36.0: `compact update`가 실패하면 [릴리스 파일](https://github.com/midnightntwrk/compact/releases/tag/compactc-v0.36.0)을 직접 받습니다.
3. **우리 도구(Proof Kit)는 설치하지 않습니다.** 실험 (1)·(2)는 "우리 도구 없이"가 조건입니다.
4. 빈 작업 폴더 `baseline/`를 만들고, 실험마다 하위 폴더를 씁니다.

## 실험 (1): midnight-expert만으로 만들기

- **주제 4개**(각 2회, 총 8번)
  1. 익명 투표: 투표 하나에 회원당 한 번, 선택은 숨김
  2. 봉인 입찰 경매: 마감 전까지 입찰가 숨김, 마감 뒤 낙찰
  3. 나이·신용 자격 증명: 발급자가 발급하고, 사용자는 "기준 이상"만 증명
  4. 헬스장 출석 보상: 월 출석 횟수는 숨기고 "10회 이상"만 증명해 보상 수령(개발에 쓰지 않은 주제)
- **매번 새 세션**에서 시작합니다. 같은 주제의 두 번째 회차도 새 세션입니다.
- **프롬프트**(주제 문장만 바꿔 그대로 씀):
  > Midnight Compact로 `<주제 문장>` 계약을 만들어 줘. 숨겨야 할 값이 체인에 드러나지 않게 해 줘. compiler 0.36.0으로 `compact compile --skip-zk`가 통과해야 해. 다 만들면 계약 파일과, 무엇을 숨기고 무엇을 공개하는지 짧은 설명을 `DESIGN.md`로 남겨 줘.
- **개입 규칙**
  - 컴파일 오류는 "고쳐 줘"까지만 말합니다.
  - 설계 방향은 주지 않습니다. 질문을 받으면 "네가 판단해"로 답합니다.
- **저장**: `baseline/exp1/<주제번호>-<회차>/` 아래에 세 가지를 둡니다.
  - `.compact` 파일
  - `DESIGN.md`
  - 대화 요약: 사용자 메시지와 마지막 답변만, `transcript.md`

## 실험 (2): `/audit-compact`로 고치기

1. 실험 (1)의 결과 8개 각각에서 `/audit-compact`를 실행합니다.
2. 보고서를 `audit.md`로 저장합니다.
3. "보고된 문제를 모두 고쳐 줘"로 고치게 한 뒤, 고친 계약을 `fixed/` 아래에 저장합니다.
4. **저장 위치**: `baseline/exp2/<주제번호>-<회차>/`

## 겹침 확인: 우리 시나리오에 `/audit-compact`

이 레포(`thisismycosmos/krnightforce`, 브랜치 `feat/engine-core`)를 받아 아래 각 구멍 판에서 `/audit-compact`를 실행하고, 보고서를 `baseline/overlap/<이름>.md`로 저장합니다.
- `bench/blind/*/holed/` 4개: 엔진을 모르는 세션이 만든 시나리오
- `bench/scenarios/*/holed/` 8개

정답(구멍 목록)은 `bench/blind/*/holes.md`와 `bench/scenarios/*/answer.json`에 있습니다. 보고서를 다 받기 전에는 열어 보지 않는 것이 공정합니다.

## 고정 점검표 (실험 (1)·(2) 구멍 세기)

계약마다 아래 항목을 "있음 / 없음 / 판단 불가"로 적습니다. 도구와 무관한 기준이며, `docs/design-guide.md`의 설계 기준 번호를 괄호에 적었습니다.

| # | 항목 |
| --- | --- |
| 1 | 숨겨야 할 값이 그대로 장부에 들어감 (1) |
| 2 | 경우의 수가 작은 값을 해시(소금 없음)해서 공개 (4) |
| 3 | 커밋의 소금이 상수·재사용·비밀에서 유도됨 (5) |
| 4 | "사실"만 필요한데 값 전체를 공개 (6) |
| 5 | 숨긴 값에 따라 건드리는 장부 칸이 달라짐 (7) |
| 6 | 한 번만 할 행동에 범위(투표·기간) 없는 nullifier, 또는 행동끼리 이어짐 (8) |
| 7 | 사용자가 넣는 값을 아무도 보증하지 않음 (10) |
| 8 | `ownPublicKey()`로 권한 확인 또는 장부 저장 (11) |
| 9 | 한 회로에서 같은 비밀 witness를 두 번 읽음 (10) |
| 10 | 호출자가 주는 시각·회차를 그대로 믿음 |
| 11 | 컴파일 실패로 완성되지 않음 |

## 결과 넘기기

`baseline/` 폴더 전체를 아래 둘 중 한 가지로 넘깁니다.
- zip으로 묶어 대화에 첨부
- 이 레포의 브랜치 `baseline/run-1`에 push

계약은 사용자가 만든 것이라 공개 레포에 올려도 됩니다. 단, 대화 요약에 개인 정보가 있으면 지우고 올립니다.

2. 겹침 확인: 구멍마다 세 칸 표(우리 엔진 / `/audit-compact` / 둘 다 놓침).
