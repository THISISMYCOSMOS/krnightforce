# 인계 (2026-11-24)

다음 세션이나 다른 작업자가 이어받을 때 먼저 읽을 파일입니다. 기획의 기준은 [plan.md](plan.md)이고, 이 파일은 그 위에 "지금 어디까지 왔고 무엇이 걸려 있는지"만 적습니다.

## 작업 규칙 (사용자와 합의한 것)

- **말투와 용어**: 한국어로, 쉬운 말로 설명합니다. Midnight 용어는 정확히 씁니다. 지나치게 풀어 쓰면 오히려 틀립니다.
- **소신 있게**: 사용자가 여러 번 물어도 억지로 바꾸지 않습니다. 소신껏 최선을 고르고, 추천할 때는 이유를 붙입니다.
- **기획 변경**: plan.md를 바꾸는 일은 "기획 변경 제안"으로 따로 묻습니다. 결정 전에는 실행하지 않습니다.
- **세 기능을 한 흐름으로**: 설계(`/proof:spec`) → 공격(`/proof:attack`) → 그림(`/proof:map`)을 함께 다룹니다. 엔진만 앞세우지 않습니다.
- **판정**: 실행 결과로만 합니다. LLM은 판정하지 않습니다.
- **서브에이전트 적극 활용** (사용자 요청)
  - 서로 독립인 일은 나눠 맡깁니다. 구현은 작업 트리(worktree)에서 하고, 검토와 점검은 읽기 전용으로 둡니다.
  - 받은 결과는 직접 확인한 뒤 합칩니다.
- **git**:
  - 커밋·푸시는 `feat/engine-core`에만 합니다. main에 직접 올리지 않습니다.
  - 이 환경의 git 사용자명이 Claude라 DCO 서명(`-s`)은 넣지 않습니다. PR 때 사용자가 서명합니다.
- **외부 게시**: 이슈나 댓글을 올리기 전에 초안을 보여 주고 승인을 받습니다.
- **비공개 자료**:
  - 남의 레포 측정 원자료(레포 이름 포함)와 사용자의 개발 기록 원문은 레포에 넣지 않습니다.
  - 교훈 문서는 어떤 앱이었는지 밝히지 않습니다.

## 환경 준비

- **Compact 컴파일러 0.36.0**: `compact update`는 GitHub API 한도로 실패할 수 있습니다. 릴리스 파일을 직접 받으세요.
  - 주소: https://github.com/midnightntwrk/compact/releases/download/compactc-v0.36.0/compactc_v0.36.0_x86_64-unknown-linux-musl.zip
  - 받아서 압축을 풀면 `compactc`가 있습니다.
- **엔진 시험**:
  ```bash
  cd packages/proof-kit && npm install && COMPACTC=<compactc 경로> npm run fixtures && npx tsc --noEmit && npx vitest run
  npx --prefix packages/proof-kit biome check packages plugins docs bench   # 레포 루트에서
  ```
- **lint 주의**: 서브에이전트 작업 트리는 `.claude/worktrees/`에 생깁니다. 레포 루트에서 `biome check .`를 하면 그 안도 검사하므로, 위처럼 폴더를 지정하세요. 이 폴더는 `.git/info/exclude`로 추적에서 뺐습니다.
- **측정 원자료**: 남의 레포 이름, 코드, 결과는 `private/`(gitignore)에만 둡니다.
  - 클라우드 세션이면 세션이 끝나기 전에 `private/`를 사용자 PC나 비공개 레포로 옮깁니다. 컨테이너와 함께 사라지기 때문입니다.
  - 공개 문서에는 이름 없는 집계만 씁니다.
- **엔진을 모르는 시나리오**: 별도 클라우드 세션이 `blind/scenarios-1` 브랜치에 `bench/blind/`를 씁니다.
  - 그 세션은 엔진 코드와 기존 정답을 보지 않습니다. checkout에 `bench/schema`만 들어 있습니다.
  - 받은 뒤 엔진과 대조하고, 결과에 "정답표가 표현하지 못한 구멍"(NOT MAPPED)도 함께 셉니다.
- **진단 스크립트** (판정 아님): `packages/proof-kit/scripts/`
  - `count-witness-reads.mts`: 회로마다 witness를 몇 번 읽는지 셉니다.
  - `probe-witness-reads.mts`: 실험 p29를 실행합니다.

## 알려진 한계

- **조건식 미해석**: 누출 설명의 `fact`는 조건식을 해석하지 않습니다. 그래서 "100% 이하만 허락"했는데 "50% 이하인지"가 따로 새는 경우를 못 잡습니다.
- **기준 번호 부정확**: A2 실패에는 기준 4·5가 기계적으로 붙습니다. 블록 시각 비교로 새는 경우처럼 실제로 어긴 것이 기준 6일 때가 있습니다.
- **기본값이 범위 밖일 수 있음**: 숨긴 입력의 기본값은 정수면 37입니다. 누출 설명의 범위 밖이면 A2 복원이 되지 않을 수 있습니다.
- **두 witness를 섞는 관계**: `hash(a, b)` 같은 관계는 아직 찾지 않습니다.
